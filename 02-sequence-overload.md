# Диаграмма последовательности № 2: переполнение буфера и отказ

Сценарий иллюстрирует важное правило варианта № 7: при занятости всех серверов и заполнении буфера **отказ получает не новый кадр, а самый старый ожидающий кадр** (Д10О3).

```mermaid
sequenceDiagram
    autonumber
    actor Camera as Камера парковки
    participant Receive as Модуль приёма кадров
    participant Dispatch as Диспетчер
    participant Buffer as Буфер снимков
    participant Stats as Статистика моделирования
    participant Server as Сервер распознавания
    participant Board as Информационное табло

    Note over Dispatch,Server: Все серверы заняты
    Note over Buffer: Буфер полон: [кадр 21 (старый), кадр 22, кадр 23 (новый)]
    Camera->>Receive: Новый кадр 24
    Receive->>Dispatch: Передать кадр 24
    Dispatch->>Buffer: Проверить наличие свободного места
    Buffer-->>Dispatch: Свободных мест нет
    Dispatch->>Buffer: Удалить самый старый ожидающий кадр 21 (Д10О3)
    Buffer-->>Stats: Зафиксировать отказ кадра 21
    Dispatch->>Buffer: Поместить кадр 24 в конец (Д10З2)
    Note over Buffer: Теперь буфер: [22, 23, 24]
    Server-->>Dispatch: Один сервер завершил предыдущий кадр
    Dispatch->>Buffer: Выбрать последний ожидающий кадр (Д2Б2, LIFO)
    Buffer-->>Dispatch: Кадр 24
    Dispatch->>Server: Передать кадр 24 на обработку
    Server->>Server: Анализ парковочных мест (ПЗ2)
    Server-->>Board: Отправить результат для кадра 24
```

**Важно:** уже обслуживаемые сервером кадры не удаляются. Удаление касается только очереди ожидания. Номера 21–24 — условные идентификаторы для иллюстрации, а не фактические параметры системы.
