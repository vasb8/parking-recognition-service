# Первичные артефакты — система распознавания свободных мест на парковке ТЦ

**Предметная область:** обработка снимков камер парковки торгового центра для определения свободных парковочных мест и отображения результата на табло.

**Вариант № 7:** `ИБ ИЗ1 ПЗ2 Д10З2 Д10О3 Д2П1 Д2Б2 ОР1 ОД1`.

> Это проектные артефакты, а не действующий программный сервис. Правила модели взяты из документов «Бизнес-домен» и «Маппинг». Дополнительные численные параметры, которые в документах не заданы, не выдуманы.

## 1. Назначение

Камеры видеонаблюдения создают снимки парковочных зон. Система принимает снимки, передаёт их серверам распознавания, находит автомобили на изображениях, подсчитывает свободные места и отправляет результат на информационное табло парковки.

При загруженности вычислительных серверов снимки ожидают в ограниченном буфере. При переполнении удаляется **самый старый ожидающий снимок** (Д10О3), чтобы новый кадр занял его место. При освобождении сервера на обработку выбирается **последний поступивший в очередь кадр — LIFO** (Д2Б2). Эти два правила не следует путать.

## 3. Ключевые сущности

- **Источник:** камеры видеонаблюдения, создающие поток снимков (ИБ, ИЗ1).
- **Заявка:** кадр с идентификатором камеры, номером снимка, временем съёмки и изображением парковочной зоны.
- **Буфер:** очередь снимков ограниченной вместимости, пополняемая в порядке поступления (Д10З2).
- **Прибор:** сервер распознавания автомобилей, обрабатывающий один кадр за раз (ПЗ2).
- **Диспетчер:** направляет кадры на свободные серверы либо в буфер и применяет правила выбора/отказа.
- **Результат:** число свободных парковочных мест, передаваемое на табло.

## 4. Правила имитационной модели

| Обозначение | Смысл |
|---|---|
| ИБ | Условно бесконечный источник заявок |
| ИЗ1 | Пуассоновский поток поступления заявок; интервалы между ними экспоненциальные |
| ПЗ2 | Равномерное распределение времени обработки кадра |
| Д10З2 | Запись ожидающего кадра в буфер по порядку поступления |
| Д10О3 | При переполнении вытесняется самый старый **ожидающий** кадр, но не обслуживаемый |
| Д2П1 | Выбор свободного прибора по приоритету его номера |
| Д2Б2 | Выбор из буфера по LIFO: последний ожидающий кадр идёт первым на обработку |
| ОР1 | Автоматический режим со сводной таблицей статистики |
| ОД1 | Пошаговый режим: календарь событий, буфер и состояние приборов |

Направление приоритета номеров приборов (например, меньший номер — более высокий приоритет) и численные параметры **не фиксируем без методички**, так как в имеющихся исходных документах они не указаны.

## 5. Основные сценарии

**Сценарий А — сервер свободен.** Камера отправляет кадр. Диспетчер по приоритету номера выбирает свободный сервер, передаёт кадр, сервер формирует число свободных мест, табло получает результат.

**Сценарий Б — все серверы заняты, но место в буфере есть.** Новый кадр добавляется в конец очереди. После освобождения сервера из очереди выбирается последний добавленный кадр (LIFO).

**Сценарий В — все серверы заняты и буфер полон.** Самый старый кадр из буфера удаляется с отказом, новый добавляется в освободившееся место. Обслуживаемые сервером кадры не вытесняются.

## 6. Что остаётся определить при переходе к реализации

Число серверов, вместимость буфера, интенсивность потока кадров, нижнюю и верхнюю границы равномерного времени обслуживания, правила агрегации результатов по парковочным зонам и стратегию предотвращения публикации устаревшего результата. Это проектные параметры, а не факты из исходных PDF.
